<Aside type="caution" title="Early development">
The loop is closed end to end — a work gains versions, a version earns a score, a score wins a calendar slot, and the slot ends in a release you mark by hand — with four craft profiles, plugins, and an AI panel over your own Claude Code CLI. Deletions go to a trash and changes go to a history, so nothing is lost and nothing happens unnoticed. [Builds exist](https://github.com/lacodda/kilna/releases) for Windows, macOS and Linux, none of them signed yet. The interface is being rebuilt toward 1.0 on its own design system, dark by default.
</Aside>

## What kilna does

<CardGrid stagger>
	<Card title="A first screen that answers what now" icon="star">
		kilna opens on what needs a decision — a slot this week the work is not ready for, overdue first — then the week as it stands, then the shortlist of scored work going nowhere yet. Already-released work never appears: the automation shows only what can still be done. Standing findings sit below — a stale score, a weak slot, a draft that stopped moving — each offering the profile action that answers it, and changing nothing until you press it.
	</Card>
	<Card title="Work with versions" icon="document">
		Every draft is kept whole — no diff chains, no lost revisions. A song keeps lyrics and style separately; a chapter keeps text and outline.
	</Card>
	<Card title="Scoring that means something" icon="seti:todo">
		Rate a work along axes you define, weighted into a tier. Scores are snapshots tied to a version, so you can see that rewriting the second verse moved it from 62 to 78.
	</Card>
	<Card title="A calendar that pushes back" icon="rocket">
		Slots compete. A stronger work bumps a weaker one out of Thursday — the weaker one returns to the queue with its plan intact, not deleted. The outcome shows before the drop, every chip says whether it could actually go out, and one click lays the whole queue out to your rhythm — as a preview you approve, never a booking you discover.
	</Card>
	<Card title="Shipping is a state, not an integration" icon="approve-check">
		Mark it out, paste the link. Plugins can automate it later; the loop closes without them.
	</Card>
	<Card title="Profiles, not a form builder" icon="setting">
		Music, Novel, Podcast and Blog ship as configuration, not code. Switch profile and the same screens speak about chapters and pull, or episodes and the cold open.
	</Card>
	<Card title="Nothing happens unnoticed" icon="list-format">
		Every change is written down. History answers *what happened to this, and when* three weeks later, and the bell lights only for the things that need a look — like a release that lost its slot.
	</Card>
	<Card title="Your data stays yours" icon="lock">
		Local SQLite, media as plain files on disk, and a markdown export of everything. No account, no server, no lock-in.
	</Card>
</CardGrid>

## Profiles, not a form builder

A song, a chapter, and a podcast episode differ in vocabulary and in how they're judged — not in structure. So the schema is fixed and the craft is configuration:

```jsonc
{
  "work_kinds":    ["song"],
  "release_kinds": ["clip", "short", "audio-release"],
  "axes": [
    { "key": "hook", "label": "Hook", "weight": 2,   "scale": 10 },
    { "key": "text", "label": "Text", "weight": 1.5, "scale": 10 }
  ],
  "tiers": [{ "key": "clip", "min": 75 }, { "key": "hold", "min": 0 }]
}
```

kilna ships with **Music**, **Novel**, **Podcast** and **Blog**. No new code, no migration — the schema never moves.

## AI panel

kilna talks to Claude through your installed [Claude Code](https://claude.com/claude-code) CLI — your subscription, your session, your skills. Nothing is sent anywhere else, and there is no API key to configure. The core works without it: if the CLI isn't installed, the panel says so and everything else carries on.

A question starts a run that belongs to its chat, not to the screen you asked from — leave, come back, it is still going, and a floating button reaches every chat from anywhere. Your profile's actions run straight from a work's card too, each in a chat of its own, telling you when they land — or from the catalogue against everything you have ticked, three at a time with the rest queued — and saying so on every screen when one stops to ask you something. An action can come back with a score along your axes, laid out for you to apply or ignore; the assistant proposes and never writes. Answers render as markdown, and one worth keeping becomes a version of the work with one click. See [The assistant](/kilna/guides/the-assistant/).
